### 1.2 تغطية حدود المسارات (route boundaries)

كل مسار عام وكل مقطع رئيسي له `loading.tsx` + `error.tsx` — تم التحقق ملفًا ملفًا:

| المسار | loading.tsx | error.tsx | الشكل |
|---|---|---|---|
| `/` (الجذر) | — | `app/error.tsx` ✓ | DefaultError |
| أي مسار غير معالج | — | يرث الجذر | DefaultError |
| `/dashboard` + كل أبنائه | `dashboard/loading.tsx` ✓ | `dashboard/error.tsx` ✓ | DefaultLoading/DefaultError |
| `/admin` + settings + support | `admin/loading.tsx` ✓ | `admin/error.tsx` ✓ | DefaultLoading/DefaultError |
| `/admin/telegram` | مخصص ✓ | مخصص ✓ | Loader2 spinner + شاشة خطأ عربية مصممة مع زرين |
| `/login`, `/register`, `/subscribe`, `/pricing`, `/demo`, `/terms`, `/privacy`, `/connect` | ✓ الكل | ✓ الكل | DefaultLoading/DefaultError (توأم واحد من سطرين) |
| `global-error.tsx` | — | ✓ | شاشة عربية كاملة `<html lang="ar" dir="rtl">` + إعادة المحاولة + العودة للرئيسية (`app/global-error.tsx:32-56`) |
| `not-found.tsx` | — | ✓ | 404 مصمم (h1 متدرج + زرا رئيسية/لوحة) (`app/not-found.tsx:5-34`) |

**ملاحظة بنائية:** صفحات dashboard الفرعية الـ22 لا تملك `loading.tsx` خاصة بها — تِرث `dashboard/loading.tsx` (سبينر عام). هذا مقبول وظيفيًا (Next.js App Router) لكنه أضعف من السكلتونات داخلية الصفحة: أثناء التنقل بين مسارات dashboard يظهر سبينر مركزي بدل الحفاظ على الشل. **P3 (اتساق بصري فقط).**

### 1.3 طبقة التغذية الراجعة (toast)

- `brandedToast`/`premiumToast` (`src/lib/premium-toast.tsx:59-80`): بطاقة RTL مصممة، أيقونة ملوّنة، زر إغلاق بعربي.
- **فصل ARIA حسب الخطورة**: `role="alert"` للأخطاء والحذف، `role="status"` للبقية (`premium-toast.tsx:51-63`) — إشعار خطأ يُعلن فورًا للقارئ الشاشي.
- `AppToaster` (`src/components/ui/app-toaster.tsx:17-24`): `dir="rtl"` + `containerAriaLabel="الإشعارات"` (كان «Notifications» إنجليزيًا — أُصلح v12-E4.4) + تتبع الثيم.
- Toaster مركّب في `dashboard/layout.tsx:33` فقط (الصفحات العامة لا تشحن sonner — قرار حجم حزمة موثق `:21-27`).

## 6. فحص صياغة الحالات (العربية / الإنجليزية / placeholders)

- **لا تسرب إنجليزي في نصوص الحالات**: بحث regex عن `(Loading|Error loading|Failed to|No data|Something went|Please try|Loading\.\.\.)` في `src/app` أعاد **نتائج أسماء متغيرات فقط** (isLoading/error) — لا نص معروض للمستخدم بالإنجليزية. ✓
- كل عبارات الحالات عربية أصيلة: «جارٍ التحميل…» (sr-only في كل سبينر: `AuthGuard:109`، `admin:142`، `admin/settings:279`، `telegram:235`، `support:389`…)، «فشل تحميل X»، «إعادة المحاولة»، EmptyStates بوصف عربي مفيد («ستظهر محادثاتك مع العملاء هنا فور وصول أول رسالة»…).
- `DefaultError.tsx:36-39` **يحجب رسالة المتصفح الإنجليزية الخام** عمدًا ويعرض نسخة عربية ثابتة + digest — مُوثق بالتعليق.
- الجمع العربي المثنى/الجمع عبر `countPhrase` في كل النصوص الكمية («إشعاران غير مقروءان» notifications:190، «مشتركين» marketing:116) — بلا `${n} items` خام.
- Placeholders تقنية مقصودة LTR فقط حيث يجب (توكن/IBAN/هاتف `dir="ltr"` أو `dir="auto"` — توثيق v14-E5/v16-E3 في كل موضع).
- القيم الحية (أسماء/رسائل فيسبوك) معزولة `dir="auto"` لمنع كسر bidi (leads:64، comments:112، messages:72، admin/support:223-239…).
- الحالة الوحيدة «نص خام بلا EmptyState مصمم» المتبقية: بطاقات الأخطاء النصية في 5.3/5.4/5.5 — عربية لكن أقل وزنًا بصريًا من `ErrorState`.

1. **نمط «التعطيل الصفّي الدقيق»** (`mutation.isPending && mutation.variables === rowId`) مطبق في 8 صفحات (autoreply، comments، posts، scheduled، tools، marketing، admin، notifications) — يمنع تعطيل الجدول كله أثناء عملية صفٍّ واحد.

3. **حالات إعداد مخصصة (setup states)** مميزة عن الأخطاء العامة: needsSetup في messages (400→CTA ربط صفحة `:218-241`)، «غير متصل» في dashboard الرئيسية، قائمة فحص الويبهوك في connect — تفرّق بين «بيانات فارغة لأن الصفحة غير مربوطة» و«خطأ».

5. **حذف المسودة عند النجاح فقط** (v9-B5) في comments — لا يفقد المستخدم نصه عند فشل الرد.
