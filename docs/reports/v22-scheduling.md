## 1. دورة حياة المنشور المجدول (حيّة، post id=28)

| الخطوة | الدليل | النتيجة |
|---|---|---|
| إنشاء منشور مجدول (+115 ث) | `POST /api/scheduled-posts` (Form) → 200 `{id:28, status:"scheduled"}` | **PASS** |
| صف DB قبل الاستحقاق | `status='scheduled', scheduled_at=14:52:00, published_at=NULL` | **PASS** |
| قيادة النبض عند الاستحقاق | heartbeat (Bearer) → `{published_posts:0, fan_refreshed:3, cycles:3, errors:[], webhook_checked:3}` | **PASS** (سياسة v14-E2) |
| الحالة بعد النبض | `status='scheduled'` — بلا تغيير | **PASS** — **السياسة المقصودة** |
| نشر يدوي (مستأجر بلا صفحة) | `POST /api/scheduled-posts/28/publish` → **400 «لا توجد صفحة فيسبوك مرتبطة بحسابك — اربط صفحتك أولاً»** | **PASS** — خطأ صادق عربي (لا 500، لا نشر صامت) |

**تفسير السلوك (من الكود، routers/bot.py `_publish_due_scheduled_posts`):** المستأجر غير المرتبط بصفحة → المطالبة الذرية (claim `scheduled→publishing`) تُطلق ثم تُحرَّر فوراً إلى `scheduled` (سياسة v14-E2: يُنشر عند ربط الصفحة لاحقاً). النبض لم يبعث `errors` لأن هذا مسار مقصود لا فشل. **النشر الفعلي على فيسبوك لا يمكن إثباته إلا لمستأجر مرتبط (t22/23/24/25 — حسابات المالك الحقيقية): عُلِّم كبند تحقق المالك في §الخلاصة.** حراسة المطالبة الذرية (منع النشر المزدوج D12-H1) مغطاة باختبارات الوحدة الموجودة (content_calendar claim tests) + المنطق نفسه المُنشَر.
