## 4. Deliberate decisions / deviations (all documented in-code with `/* v24-C3 */` tags)

1. **`['me']` excluded from sessionStorage persistence** — the task text didn't list exclusions, but A2 §9 #3 explicitly says "never persist ['me']", and same-tab user-switching (logout→login-as-other-user) would otherwise hydrate the previous account's profile into the next session's auth gate. Mitigated for all other keys by clearing the store on logout. In-memory sharing still delivers the per-navigation de-dupe (task 1/2's core win) since the QueryClient lives in the persistent layout.
2. **`refetchInterval: 60 s` on the shared `['me']`** — replaces v19's per-pathname refetch so the sidebar subscription CTA stays honest (a mid-session admin approval flips it within a minute); the task's "if it needs different freshness, use staleTime + refetchInterval" clause. One light GET/min vs. the old 2 per navigation.
3. **Cold load still shows the guard spinner** (children gated on first real user) — "render children immediately once 'me' is in cache" is honored exactly: cached → instant, uncached → the gate holds (the tests pin children-never-render-before-auth, preserved). In-shell navigations are the waterfall the A2 report targeted, and they are now zero-RTT.
4. **`onNavigate` kept as an optional interceptor prop** (task said it "can remain for logout only") — logout uses its own `onLogout`; `onNavigate` survives solely because `/demo` (outside my ownership, cannot be edited) drives its tab switcher through it. In the real shell it is no longer passed: nav is pure `<Link>`. In interceptor mode prefetch is explicitly disabled.
5. **QueryProvider hydration is post-mount (useEffect), not in the useState factory** — synchronous restore would paint cached data on the first client render while the server HTML has skeletons → hydration mismatch. Post-mount restore still lands before the network would (instant paint for non-active entries + stale-while-revalidate for the active page).
6. **One extra 401-toast path on session-expiry-via-me-poll**: the shared queryFn goes through `apiFetch` (single-arg — the shape useSubscriptionStatus tests pin), so a 401 fires apiFetch's global journey (toast + delayed replace) before the guard's immediate redirect wins. User-visible outcome is identical to the old guard (straight kick to `/login?redirect=…`); documented in `useMe.ts`.
