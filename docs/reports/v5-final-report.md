## الأخطاء الحقيقية التي اصطادتها v5 (ولم يصطدها أحد قبلها)

1. **6 اختبارات فاشلة في المجموعة الكاملة كانت خضراء زوراً في التقارير السابقة** — الجذر: متغير `DATABASE_URL` ملوِّث من الجهاز (`file:/home/z/my-project/db/custom.db`) يتسرب لـ pytest، وconftest القديم بشرط `if not DATABASE_URL` تخطّى إعداده بالكامل. الحتمية الآن مفروضة بالقوة لا بالأمل.
2. **خطأ إنتاجي (500): `POST /api/flows/{id}/test`** — `current_user` غير معرّف في التوقيع (ruff F821 وجده). كل استدعاء كان ينهار. أُصلح + اختبار انحدار.
3. **مُصدِّر النشر `app` في `api/index.py` حذفه ruff** كـ«استيراد غير مستخدم» — **كل عمليات نشر API توقفت صامتة لساعات** بينما الكود «أخضر» محلياً. أُصلح بصيغة re-export الصريحة + اختبار انحدار يجعل هذا الصنف صاخباً. (رسالة الفشل الثانية التي علّمتني: أي أداة آلية تحتاج بوابة تعاقب حتى أخطاء الأداة نفسها.)
4. **CI اصطاد أول خطأ له خلال ساعات من إنشائه** — سير العمل ضبط `CRON_SECRET=ci-cron-secret` بينما الاختبارات ترمّز توكن اختبارياً → 403 في CI فقط. الجذر: conftest بـ`setdefault` لا «فرض». فُرضت القيم القانونية — الحتمية تعني تثبيت العالم كاملاً.
5. **قوس سبينر التحميل كان شفافاً على كل صفحة** — كلاس `border-t-orange` يشير لعائلة توكن حُذفت في v4 (لا أحد راجع الاستخدامات النصية في className). 
6. **بطاقة إحصائية عائمة تنزف 4px خارج شاشة 375px** بشكل متقطع (التقطها مسح viewport بعد تكراره — درس: الفحص المتذبذب يجب أن يُكرَّر).

## حالة الإنتاج بعد v5 — حقيقة كاملة

| الطبقة | الحالة | الدليل |
|---|---|---|
| **الواجهة (bot.smart-link.ly)** | ✅ **v5 حية بالكامل** | h3 الفوتر + مسح a11y 7/7 + رحلة 8/8 (كلها تختبر كود v5 على رابط الإنتاج) |
| **API (api.smart-link.ly)** | ⚠️ ما زال كود v4 (فعّال 100%) | `/api/health` version=2.0.0 والكناري `2.0.1-v5canary` لم يظهر بعد 20+ دقيقة من الدفع — مشروع API لا ينشر من git تلقائياً |

**تشخيص عملية النشر:** الواجهة على Vercel مرتبطة بـ git (تنشر تلقائياً — تحقّق حياً). مشروع API لا يستقبل الدفعات (جلسات v3/v4 كانت تنشره يدوياً بـ `vercel --prod` بامتلاك التوكن). كل تحسينات الخلفية v5 (N+1 + الفهارات + مسار الاشتراكات + إصلاح flows + المراقبة) موجودة على main وCI أخضر — **بانتظار نشر واحد**.

### خطوة المالك الوحيدة (دقيقتان)
1. Vercel Dashboard → مشروع **smart-bot-api** → Deployments → **Redeploy** من آخر Commit على main (`0371e6b1`) — أو من الطرفية: `cd SmartBot && vercel --prod` بالتوكن.
2. عند الإقلاع الأول: الترحيل 010 (الفهارات) يُطبَّق **تلقائياً** (lifespan يشغّل `alembic upgrade head`).
3. تحقق بعد دقيقتين: `curl https://api.smart-link.ly/api/health` يجب أن يظهر `"version":"2.0.1-v5canary"` — ثم يمكن إزالة الكناري بأي دفعة قادمة.

## بوابة CI (الجديدة — أول مرة في تاريخ المستودع)

```
.github/workflows/ci.yml — يعمل على كل push/PR إلى main + develop:
  Gate 1: ruff check (lint)
  Gate 2: pytest الأمامي + pytest العكسي (الحتمية بوابة لا أمل)
  Gate 3: tsc --noEmit
  Gate 4: next build
```

الحالة على الالتزام الأخير: **success** — نفس فشل اليوم (CRON_SECRET) لو حدث غداً لَاصطاده CI قبل أي نشر.

## ما ينتظر المالك وحده

1. **نشر مشروع API من Vercel** (الخطوة أعلاه) — كل شيء آخر حي.
2. مدخلاته السرية كما في v4 (App Secret، ربط صفحته، توكن BotFather، بيانات الدعم، cron-job.org).
3. **إبطال كل التوكنات** (GitHub PAT المستخدم في هذا المستودع + أي توكن Vercel) بعد الانتهاء — وتغيير كلمة المرور من الواجهة.

## ملاحظات هندسية صادقة

- **قابلية تكرار الفحوص:** كل أمر في جدول الحسم يمكن للمالك نسخه وتشغيله بنفسه.
- **التغطية الكلية** 46% على مستوى المستودع كاملاً؛ المحركات الحرجة: rate_limit 100%، subscription_decisions 100%، cache_layer 92%، messenger 76%. bot.py 52% — أعمق مسارات الكومة (تحليل النوايا، الحملات) تحتاج تكاملاً حياً مع Graph لا محاكاة فقط — موثّق كحدّ معلن لا كادعاء.
- **الحزمة 881KB خام**: مقاسة، موزّعة، dominated بـ vendor مشترك بين الصفحات — أي تقسيم إضافي marginal ومخاطره أعلى من مكسبه لهذا حجم التطبيق.
- **الحتمية بأي ترتيب كشفت 3 فئات تلوث** (كاشات عامة، عدّاد محاولات مشترك بIP واحد، توقع ترتيب في اختبارين) — كلها مغلقة الآن عند حدود الملفات.
