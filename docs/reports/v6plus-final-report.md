## 1. نقطة البداية: اكتشاف حقيقة النشر (تصحيح تقرير v6)

تقرير v6 ختم بأن «الـAPI ما زال كود v4 ويحتاج Redeploy». **فحص مباشر بعد الجولة كذّب ذلك** — أحداث النشر الأخيرة نجحت فعليًا:
- `/api/cron/alert-test` (مُسار v6 §C) يردّ 401 «غير مصرح به» = **المسار موجود = كود v6 §C منشور**
- `/api/cron/heartbeat` يردّ 403 «Unauthorized cron» = حماية CRON_SECRET v6 تعمل
- `/api/health` = `2.0.1-v5canary` (canary v5) · `/healthz` = plans:5, database:ok
- الواجهة: h1 كامل + robots.txt + /subscribe عامة (تحقق v6 الحي)

الخلاصة: **الإنتاج كله (واجهة + API) يعمل على كود v6**. لا يوجد «إعادة نشر معلّقة» — الحد استُنفد ثم أُعيد ضبطه ونجحت الدفعة الأخيرة.

## 4. التحقق التفاعلي (متصفح حقيقي بعد التحويل)

- 17 عنصر `.reveal` تنكشف عند التمرير — نظام CSS الجديد يعمل بفرamer ولا شيء آخر
- لوحة «المزيد» السفلية: تفتح/تغلق بانتقال CSS (`SHEET OPEN OK`) — بديل AnimatePresence كامل الوظيفة
- KineticText: opacity محسوبة = 1 بعد الدخول (الانتقال أُطلق)
- صفر أخطاء console على /، /pricing، /demo — سطح مكتب وجوال
- VLM على اللقطات: البطل مكتمل (عنوان+أزرار+موك-أب)، لا تراكب، ثيم متسق، مخطط demo سليم
- لقطات موثقة: `docs/screenshots/v6plus-{landing,pricing,demo,landing-mobile,demo-mobile,demo-sheet}.png`

## 5. ما بقي خارج قدرة أي وكيل (موثّق بأمانة — نفس قائمة v6)

1. `SENTRY_DSN` + `NEXT_PUBLIC_SENTRY_DSN` في Vercel → نشر (تفعيل التتبع)
2. توكن BotFather من إعدادات الأدمن → زر «اختبار التنبيه» → لقطة تليجرام (بند 4 من جدول v6)
3. ربط صفحة فيسبوك حقيقية + App Secret + cron-job.org (خطوات المالك الموثقة منذ v3)
4. **إبطال توكن GitHub + Vercel وتغيير كلمة المرور** (القسم 0 من الخطة — بعد قبول النتيجة)
