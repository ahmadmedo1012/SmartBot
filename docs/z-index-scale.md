# SmartBot Z-Index Scale — الرسمي الوحيد (v3 final-launch plan §3)

> المصدر: نفس مقياس Smart-Menu (`--z-*` tokens في `globals.css`) — القيم متطابقة
> حرفيًا بين المشروعين. هذا الملف هو المرجع الملزم لأي طبقة جديدة.

## المقياس الرسمي (من `globals.css` — الطبقات)

| الطبقة | القيمة (Tailwind) | التوكن | الاستخدام الحصري |
|---|---|---|---|
| base | (افتراضي) / `z-0` / `z-10` | — | محتوى عادي، عناصر sticky داخل المحتوى (رؤوس بطاقات فرعية) |
| sticky | `z-20` / `z-30` | `--z-sticky: 20` / `--z-nav: 30` | الرؤوس اللاصقة للصفحات (`sticky top-0`)، الشريط الجانبي الثابت، شريط التنقل السفلي للجوال |
| dropdown | `z-40` | `--z-dropdown…` backdrop:40 | خلفية أدراج الجوال (backdrop) — `bg-black/40` |
| drawer/modal | `z-50` | `--z-modal: 50` | Dialog، Sheet «كل الأقسام»، معالج الجوال، درج /demo الجانبي |
| floating | `z-[60]` | `--z-toast: 60` | زر واتساب العائم (فوق كل شيء تحت a11y) |
| a11y top | `z-[100]` | فوق المقياس | رابط «تخطَّ إلى المحتوى» عند التركيز فقط (عادة a11y، لا يُلمس) |

## تدقيق الاستخدام الحالي (مسح `grep -rn "z-"` كامل — 2026-09-06)

| القيمة | العدد | المواضع | الحكم |
|---|---|---|---|
| `z-10` | 20 | رؤوس فرعية لاصقة داخل بطاقات الصفحات (ads/analytics/audience…) | ✅ ضمن base |
| `z-20` | 2 | عناصر sticky ثانوية | ✅ ضمن sticky |
| `z-30` | 23 | PageHeader اللاصق، AdminSidebar (عبر `--z-sticky`)، MobileBottomNav، رأس pricing اللاصق، درج demo الجانبي عند md | ✅ ضمن sticky/nav — لا تعارض |
| `z-40` | 4 | خلفيات أدراج (demo + MobileBottomNav sheet backdrop) | ✅ ضمن dropdown-backdrop |
| `z-50` | 7 | Dialog، Sheet «كل الأقسام»، OnboardingWizard، درج demo الجانبي (جوال) | ✅ ضمن modal — فوق كل sticky |
| `z-[60]` | 1 | FloatingWhatsApp (منقول من Smart-Menu حرفيًا) | ✅ ضمن toast-layer |
| `z-[100]` | 1 | skip-link (a11y) | ✅ مقبول أعلى الكل |

**النتيجة: صفر قيم شاردة، صفر تعارض طبقات** — كل قيمة تقع في شريحتها.
لا توجد قيم `z-[999]`/`z-[9999]` عشوائية إطلاقًا.

## قواعد ملزمة لأي إضافة جديدة

1. **ممنوع** كتابة `z-[<رقم عشوائي>]` — استخدم شرائح المقياس أعلاه فقط.
2. Modal جديد → `z-50`. Drawer/backdrop → `z-40`. رأس صفحة لاصق → `z-30`.
3. أي عنصر `fixed bottom-0` يجب أن يقابله `padding-bottom` في المحتوى تحته
   (DashboardShell يطبق `pb-16 md:pb-0` لكل صفحات اللوحة — تحقق يدويًا عند
   إضافة شريط سفلي جديد خارجها).
4. الحاويات التي قد تستقبل نصًا طويلًا (أسماء عملاء/عناوين عربية) تعتمد
   `truncate` أو `overflow-hidden` — راجع قاعدة التداخل الثالثة في الخطة.

## حواف حقيقية تمت مراجعتها (لا تحتاج تعديلًا)

- **AdminSidebar يضع `border-l` (فيزيائي) وهو مثبت يمينًا**: الفاصل يظهر عند حد
  المحتوى — وهو الموضع الصحيح بصريًا. (Smart-Menu يستخدم `border-s` المنطقي مع
  شريطه داخل التدفق — النية نفسها، بنية DOM مختلفة؛ كلاهما يعرض الفاصل عند
  حدّ المحتوى الخاص بتخطيطه.)
- **MobileBottomNav (z-30) تحت Dialog (z-50)**: النقر على أي زر في الشريط أثناء
  فتح Dialog مستحيل بصريًا — الترتيب صحيح.
- **FloatingWhatsApp z-[60] فوق شريط التنقل z-30**: عائم بغرض الوصول السريع،
  نفس قرار Smart-Menu حرفيًا.
